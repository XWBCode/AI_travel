# 03 · 外部数据源选型与降级规范

> 状态：草案，待 D-02 / D-03 / D-04 确认 ｜ 上位文档：总纲 V1.0 第 2.2.4、4.3、4.6、8.1 章
> 核实日期：2026-11-09。第三方来源给出的配额数字互相矛盾，本文件**不写死额度**，只记录可从官方条款确认的部分。

## 1. 结论先行：L0 / L1 分层

当前状态：本机 MySQL 已就绪；**大模型 key 与天气 / 地图数据源均未取得**。如果按常规做法等数据源到位再开发，M1 会被无限期阻塞。

本文件给出的架构判断：

| 层 | 前提 | 能力 | 数据可信度 |
|---|---|---|---|
| **L0 基础层** | 仅需大模型（或 mock） | 生成结构化行程、每日安排、景点分组、预算框架、注意事项 | 实时性字段一律 `verified=false`，显示「待核实」 |
| **L1 增强层** | 外部 Tool 就绪 | 注入天气、地理距离、POI 开放信息、交通耗时 | 携带 `source` + `fetchedAt`，前端展示来源与更新时间 |

**L0 是必做且现在就能做；L1 是可插拔增强，不阻塞 M1/M2。** 两层共用同一份计划 Schema（见 05），差别只在 `FactField` 的取值来源。这让采购与开发解耦。

> 这条设计直接落实总纲 2.2.4：「没有实时数据时，不允许 AI 编造天气、车次、票价、开放时间等信息」——办法不是"等数据"，而是**让数据结构本身无法承载编造值**。

## 2. `FactField` 契约（核心）

所有带实时性的字段，一律不用裸值，统一包成：

```json
{
  "value": null,
  "display": "待核实",
  "source": "NONE",
  "verified": false,
  "fetchedAt": null,
  "expiresAt": null,
  "note": "尚未接入天气数据源"
}
```

| 字段 | 类型 | 约束 |
|---|---|---|
| `value` | any \| null | `verified=false` 时**必须为 null**（L0 强制） |
| `display` | string | 前端展示文案，L0 固定为「待核实」或「暂不可用」 |
| `source` | enum | `NONE` / `MODEL_KNOWLEDGE` / `USER` / `TOOL` / `CACHE` |
| `verified` | boolean | 仅 `TOOL` 或有效期内的 `CACHE` 可为 true |
| `fetchedAt` | datetime \| null | `TOOL`/`CACHE` 必填 |
| `expiresAt` | datetime \| null | 用于缓存过期判断 |
| `note` | string | 降级原因，便于用户理解 |

**规则**：

- **U**：`source != TOOL/CACHE` 时，`verified` 必须为 `false`，且 `value` 必须为 `null`。
- **U**：`MODEL_KNOWLEDGE` 只能用于**非实时**的描述性内容（如「大理以洱海闻名」），不得用于数值型实时字段。
- **U**：Schema 校验层强制检查上述约束，违反即拒绝落库（对应 R-14、AC-08）。
- **U**：前端渲染 `FactField` 时，`verified=false` 一律显示灰色「待核实」标签，禁止渲染成普通数值。

**适用于 `FactField` 的字段**：天气（温度/降水/风力）、景点开放时间、门票价格、车次与票价、景点间交通耗时、实时路况、酒店价格。

## 3. 数据源候选

### 3.1 天气

| 候选 | 是否需要 key | 官方条款要点 | 适用阶段 |
|---|---|---|---|
| **Open-Meteo**（免费端点） | 否 | 免费 API **仅限非商业用途**，< 10,000 次/日、5,000/小时、600/分钟；数据 CC BY 4.0 **需署名**；商用或更高调用量需订阅付费端点 [^1][^2] | 本地开发 / 内部演示 |
| **和风天气 QWeather** | 是 | 官方称注册后可创建免费订阅项目与 KEY，采用按量计费、无需预付 [^3]；国内城市数据与中文生活指数较全 | 面向国内用户的正式产品 |
| **高德天气查询**（Web 服务） | 是 | 属高德「Web 服务端产品」，官方标注基础服务 API 免费、按接口给每日免费调用量并区分开发者类型 [^4] | 已用高德 LBS 体系时顺带接入 |

**额度说明**：多个第三方来源分别给出「1,000 次/日」「5 万次/月」等互相矛盾的数字，**均不作为设计依据**。接入前必须由技术负责人在服务商官网当日核验并记入决策记录。

> ⚠️ **合规红线**：Open-Meteo 免费端点**明确禁止商业使用**（含带广告、带订阅的产品）[^2]。本项目若未来商用，不能直接把免费端点带上线；可选订阅、换源，或自托管其 AGPLv3 服务端（仍需注意数据署名义务）。这条要写进上线检查清单。

### 3.2 地理 / POI / 距离

| 候选 | 是否需要 key | 官方条款要点 | 适用阶段 |
|---|---|---|---|
| **高德 Web 服务 API**（地理编码、POI 搜索、路径规划、距离测量） | 是 | 官方列出这些基础服务 API 免费、按接口给每日配额且按开发者类型区分 [^4] | 需要真实距离时 |
| **地图 JS API**（前端嵌图） | 是 | **商用需单独购买商业授权**，个人 / 认证个人 key 通常限定非商业使用 [^5] | MVP 不引入 |

**MVP 决策建议（D-04）**：不引入地图能力。理由是它不仅带来 key 与配额问题，还有商用授权与测绘资质合规成本，而 MVP 的用户价值并不依赖精确距离。L0 阶段只做**同城/同区域分组**，并在界面提示「景点间耗时未核实」，由用户自行拖拽调整顺序（R-33）。

### 3.3 交通（火车票）

总纲 2.2.4 已明确「火车票实时查询作为后续独立模块」，本包沿用：**MVP 不做**。列车班次、票价属于强实时且强合规的数据，无授权来源时模型绝不能给出具体车次。

## 4. 降级矩阵

| 场景 | 系统行为 | 前端展示 | 对应需求 |
|---|---|---|---|
| L0，无任何工具 | 计划正常生成，实时字段 `value=null, verified=false` | 灰色「待核实」+ 说明文案 | R-17 / R-18 |
| 用户主动问天气 / 车次 / 票价 | 明确回答「该信息需要实时查询，当前无法确认」 | 不展示任何数值 | R-18 |
| L1，工具首次调用失败 | 查缓存；无缓存则 `source=NONE` 降级 | 「暂不可用」 | R-32 |
| L1，缓存存在但已过期 | 展示旧值 + `source=CACHE` | 「数据更新于 X 前」 | R-32 |
| L1，工具返回成功 | 写入 `value` + `fetchedAt` + 来源名 | 数值 + 「来源：XXX · 更新于」 | R-31 |
| 工具返回与计划无关的数据 | 忽略并记日志，不写入计划 | 无变化 | R-14 |
| 模型输出违反 `FactField` 约束 | Schema 校验拒绝，不落库 | 「生成失败，请重试」 | R-14 / AC-07 |

**统一原则**：宁可少给信息，不可给假信息。任何降级路径都不允许出现「看起来像真实数据」的占位值。

## 5. 禁止清单（写进 Prompt 与代码校验）

以下行为在 L0 阶段一律禁止，违反即视为 Bug（阻断上线级）：

1. 编造温度、降水概率、风力等天气数值。
2. 编造列车车次、发车时间、余票、票价。
3. 编造景点开放时间、闭馆日、门票价格。
4. 编造「车程约 30 分钟」「两地相距 15 公里」等地理数值。
5. 用固定文本冒充工具调用结果，或把 `[MOCK]` 内容当作真实数据展示。
6. 捕获异常后返回成功（总纲 9.3）。
7. 把模型知识里的历史天气当作当期天气输出。

已在 `backend-ai/app/llm/prompts.py` 的 system prompt 中写入第 1–4 条硬性规则；M1 需在 Schema 校验层补上第 5–7 条的技术拦截。

## 6. 缓存与更新策略（L1 时启用）

| 数据类型 | 建议缓存时长 | 过期行为 |
|---|---|---|
| 城市天气预报 | 30–60 分钟 | 过期后展示旧值并标注更新时间 |
| 景点基础信息（非实时） | 24 小时 | 允许继续使用，标注来源 |
| POI 坐标 / 地理编码 | 长期（按地名索引） | 不主动过期 |
| 交通耗时估算 | 按需，不长于 24 小时 | 过期后重新估算或降级 |

- **U**：外部 API 调用必须设置连接与读取超时，且不得阻塞主业务请求（总纲 8.2）。
- **U**：所有外部调用记录来源、耗时、结果摘要到日志与埋点（总纲 8.4、`external_source_fallback` 事件）。
- **U**：缓存键与响应统一归一化为自有 `FactField` 契约，前端只消费自有结构，不直接解析第三方响应。这样换供应商时前端零改动。
