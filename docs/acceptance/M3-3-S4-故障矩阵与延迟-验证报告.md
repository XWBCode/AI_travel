## 1. 结论先说：天气坏到什么程度，调整都不会失败

矩阵 20 段里，**每一段**都断言了同一件事：`code=0` 且 `ops` 通过 `validate_ops`。
不是抽样，是逐段。所以"任何天气故障不让原有调整行为改变"这句话在本次验收里是
**15 条独立断言**（见 §3.1），而不是一句设计意图。

第二件事是"不该出网就一次都不出"：关闭 / 数据源未启用 / 无日期 / 无城市 /
城市无坐标 / 全在窗口外 / 全已过去，这 7 种情形的上游调用数**全部为 0**，逐条断言。

## 3. 三条硬证据

### 3.1 故障不让调整失败（AC-A3）

`code=0` 且 `ops` 合法，出现在：关闭(1.2)、无日期(2.2)、无城市(3.2)、全过去(4.2)、
全成功(5.4)、部分失败(6.4)、全失败(7.2)、超时(8.4)、异常数据(9.3)、未启用(15.3)、
无坐标(16.3)、越窗口(17.3)、跨今天(18.4)、两城分段(19.3/19.4) —— **15 条**。

### 3.2 恢复能力的实测（不是推断）

- 超时场景（8）：成都正常、乐山 5s，预算 300ms。**快的照常入表**（8.2），
  **慢的写进"请勿为它们编造天气"**（8.3）—— 即 M3-2 用一整轮修对的"部分结果 +
  不沉默"语义，在调整链路上原样生效（D-A5 复用的直接证据）。
- 异常数据（9）：整块不注入，且 **prompt 里不出现「暂无数据」**（9.2）。
  `verified=false` 的字段被抄进表里会被模型当真实值复述，这条是防它的。
- 白名单（10、18、19）：查询用全局区间，渲染只留计划内的 `(日期, 城市)`。
  18.2 断言"跨今天的 5 天计划只入表今天起 3 天"，19.1/19.2 断言"每城只绑自己的日期"。

### 3.3 不自动重试（11.2）

两个并发请求，模型调用次数 **= 2**，与请求数相等。多出来的那次就说明发生了自动重试 ——
PM 明确不允许用重试掩盖版本冲突。判据用"调用数 == 请求数"，不是"都返回 200"。

## 4. 延迟实测（AC-A8）

本机环回、模型替身固定 120ms、每组预热 2 次（不预热时第一次建连接 66ms 会算进 P95，
让对照组反而更慢，M3-2 的 AC-9 已被这个坑坑过一次）。

| 组 | 条件 | total P50 / P95 | weather P50 / P95 | 相对 A 的增量 |
|---|---|---|---|---|
| A | 注入关闭（基线） | 124 / 125ms | 0 / 0ms | — |
| B | 注入开启、缓存已热 | 125 / 126ms | 0 / 0ms | **+0ms** |
| C | 注入开启、上游慢（5s） | 1339 / 1353ms | 1211 / 1213ms | **+1215ms** |

- C 组增量 **+1215ms ≈ 预算 1200ms（101%）**，不是"城市数 × 预算"。2 城并发查，
  预算是**整请求**的，不是每城一份。
- C 组天气耗时 P95 = 1213ms，超出预算 13ms（取消与收尾开销），仍在 ±20% 判据内。
- 三组 `code` 去重均为 `{0}`：超时也要出建议。

**为什么调整链路必须单独测**：`/v1/plan/adjust` 是同步 JSON，没有 SSE，
天气耗时 100% 叠加在用户的白屏时间里。M3-2 测出的 +4.8ms 不能搬过来 ——
那是"推迟看到内容"的时点，不是"多等一次网络"。

## 8. 已知限制（不宣称的部分）

1. **中文数字漏网**：见 §5。要堵得先做"中文数字 + 天气单位"的专门识别，
   而不是顺手扩正则 —— 误伤的代价是合法建议被拒、用户重说一遍。
2. **并发只是线程级**：`TestClient` 在进程内起两个线程，验证的是"不重试、不互相覆盖"，
   不等于验证了生产上多实例 + 数据库乐观锁的冲突概率（那是 Java 侧的 CAS，已有用例）。
3. **延迟是本机环回**：模型是固定 120ms 的替身，量的是"天气给用户加了多少等待"，
   不是真实模型的首字/总耗时。真实上游（和风）的耗时分布未在本脚本内测量。
4. **8.1 的时间判据留了 1.6 倍余量**（预算 300ms → 判 <480ms）：CI 机器上调度抖动
   会让 320ms 也出现，卡死 1.0 倍会变成假红。真正钉死"预算是整请求的"是 C 组的
   "+1215ms ≈ 1200ms"，不是 8.1。
5. **AC-A10 的样本是构造的，不是真实模型输出**：3 条中文数字用例证明的是"闸门对它们
   不生效"，不能替代"真实模型不会抄数值"的观察。真实模型的转述率仍未统计。
6. **未接真实上游**：全程用 `wx_echo.WeatherStub`，不发真实请求，也不制造真实 429/403。
   这一点与 M3-2 的口径一致。
