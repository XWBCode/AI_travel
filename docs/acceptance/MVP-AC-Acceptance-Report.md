## 4. 四项非 PASS 的说明（不含糊过去）

### AC-07 已补齐（2026-11-23 晚）：54 组，双侧断言

原先只有 10 组结构变异，样本量不足 02 §6 的「50 组」。现已拆成两层：
- **结构层 10 组**（`invalid_cases.json`）：`test_invalid_schema_cases.py` 逐组断言「被拒 + 报错路径正确」；
- **输入层 44 组**（`invalid_inputs.json`）：9 个类别（缺目的地/缺天数/地点歧义/不合理日期/不合理天数/
  空与超长输入/非旅行需求/混合意图/错误地点实体），验收脚本逐条打 `/v1/plan/intent` 实跑。

写样例时先跑一遍现状、再逐条确认期望是否合理，因此也顺带暴露并修掉了 4 类真问题：
方位词（南边/北方/海边/首都）被当成城市、句中出现的前缀（我想去/再去）被吃进城市名、
「0 天」因 falsy 判断漏过上限检查、「把这段翻译成英文」被识别成行程需求。

### AC-07 再补一次（2026-11-23 深夜）：51 组，且修掉两处「假绿」

做「提示词/校验器同源」时被新用例逼出来两个测试资产问题，都属 AC-07 的诚实性：

1. **S-3 那组反例其实没测到 S-3**：原来把 `destinations[0]` 改成另一个已有城市，
   先撞上 Schema 的 `uniqueItems`（变成重复项），被结构层拦下。五十组「全部被拒」是真的，
   但 S-3 这条规则从未被验证过。改为交换 0/1 位后，才真正命中 `S-3`。
2. **S-6 一条反例都没有**：BUG-014 能一路绿到实跑才炸，就是因为 50 组里没有一条碰过跨城段天序号。
   已补第 51 组 `S-6 跨城段 fromDayIndex 不小于 toDayIndex`。

现在 `PlanRuleCoverageTest` 会强制「每条校验器规则都必须有一条以它开头的反例，且被该规则拒绝」，
数量断言也从 `== 50` 改成 `>= 50`（口径是 02 §6 的「注入 50 组」，只会往多里加，不会为了凑数删）。

### AC-07 原判 PARTIAL 的说明（保留）

契约 `contracts/travel-plan/examples/invalid_cases.json` 现有 **10 组**畸形样例（改 verified 值守约、
状态非法、跨城缺字段、同日带跨城字段等），每组都有对应的拒绝断言，且 Java 侧
`PlanSchemaValidatorTest` 4 项、Python 侧 `test_plan.py` 27 项共同覆盖。

但 02 §6 写的是「注入 50 组」。**10 ≠ 50**，因此记 PARTIAL 而不是 PASS。
补齐方法很明确：把 10 组变异分别施加到多份合法基线计划上，凑够 50 组，脚本化后纳入 CI。
工作量约半天，不影响当前结论。

### AC-14 已补测（2026-11-23 晚）：停服实测 PASS

原先记 BLOCKED 的理由是「要停 8000 端口，验收阶段不改运行环境」。本轮为了修复另一件事需要重启服务，
顺手把这个洞补了：**先停 8000，再从 `/api/chat/stream` 发一条真实请求**。

| 观察点 | 实测 |
|---|---|
| 首字/报错延迟 | **0.1s**（没有挂到 3 分钟超时） |
| SSE 事件 | `meta` → `error{code:50201}`，文案：`AI 服务连接失败：ConnectException（请确认 http://localhost:8000 已启动）` |
| 用户消息 | `SUCCESS` 落库，不丢提问 |
| 助手消息 | `FAILED` 落库，`error_message` 记着同一句原因 |
| 刷新页面 | **原先是一个空白气泡**（原因只存库、不外传），已修：`MessageVO` 增加 `errorMessage` |

最后一条是这次补测**新发现的缺陷**（P2，已修）：`t_chat_message.error_message` 一直有值，但历史接口不返回，
所以「当时看到提示、刷新后只剩空气泡」。修法是 `MessageVO.errorMessage` + 前端 `error` 映射，
空内容再补一句「本次没有生成任何内容」的占位。

代码：`ChatController`（已有）、`MessageVO`、`ChatView.vue`；前端 174 断言与 `vue-tsc` 均通过。

### AC-15 NA：L0 阶段没有可验的数据

天气/票价/车次全部是 `verified=false` 的「待核实」占位，没有数值也就没有来源可标。
该条依赖 M3（D-03/D-04 数据源与商用授权未定）。契约里 `source`/`fetchedAt` 结构已就位，
接数据源时不需要改契约。

### AC-03 是 mock 数据，不能代表真实模型

38ms 是 mock 生成器的速度，真实模型单次计划生成 30–45 秒是已知事实（见 §7.4 实测记录）。
**这一行不能作为「首字延迟达标」的证据**，只证明「流式链路本身没有额外延迟」。

   `proxy_read_timeout 60s` 会掐断（可靠性报告 R7）。当前直连，不触发。
